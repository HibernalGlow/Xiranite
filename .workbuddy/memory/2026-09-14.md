# 2026-09-14

## vendor/ 目录架构（neoxide / mimageviewer）

**澄清：vendor/ 实际分两类，不是"7 个源码 + 二进制"：**
- **3 个 Rust 源码 fork**：`vendor/egui`、`vendor/eframe`、`vendor/egui-wgpu` —— 带 mImageViewer 补丁的 egui 0.33.3 fork。
- **5 个原生二进制/模型**：`ffmpeg`(bin+include+lib)、`pdfium`(bin+include+lib)、`ort`(onnxruntime.dll)、
  `models`(.onnx)、`susie-worker`(mimageviewer-susie32.exe) —— 运行时资产，被 `.gitignore` 忽略，构建时按 `VERSION` 下载。

**机制**：`Cargo.toml` 用 `[patch.crates-io]` 把 crates.io 的 eframe/egui/egui-wgpu 重定向到 `vendor/`；
`[dependencies]` 仍写 `version="0.33"`（标准 idiom：声明 semver 约束 + 重定向来源，不矛盾）。
`eframe/README.md`/`egui-wgpu/README.md` 明写 `## mImageViewer patch`；`eframe/Cargo.toml.orig` 留上游对照。
三个源码进 git（tracked），二进制那批不进。

## 上游状态核查（哪些 fork 还能去掉）

- **eframe**：补丁 = backport 上游 PR #7905（隐藏/最小化窗口重绘调度，修 Windows 托盘驻留 CPU 空转）。
  ✅ **已随 eframe 0.34.0（2026-03-26）合入上游**（官方 changelog 原文 `Improve behavior of invisible windows #7905`）。
  → 删 eframe fork 前必须先把整个 egui 栈升到 ≥0.34（破坏性：App::update→App::ui、panel API、wgpu 27→29、MSRV 1.88→1.92）。
- **egui-wgpu**：补丁 = 新增 mipmap 分配 + GPU mip 链生成 + mipmap 采样过滤（见其 README "mImageViewer patch"）。
  ❌ **上游没有**——上游只让你自带已有 mip 层的纹理，渲染器 `create_texture` 仍 `mip_level_count: 1`，不为托管纹理生成 mip 链。
  用途：仅 `compare_wgpu.rs`（擦除/对比）与 `panorama_wgpu.rs`（360° 全景）调 `MipmapGenerator::generate`。
  → **永久 fork**，去 vendor 的硬阻塞：要么把 mip 生成抽到应用侧（不依赖改 egui-wgpu 内部），要么保留 fork。
- **egui**：无任何 mImageViewer 补丁（grep 无 miv 标记），纯版本对齐；另两个回 crates.io 时自动跟着回。
- 上游最新已到 0.36.1。

## 360° 全景模式如何开启

- 识别条件（满足其一才算候选，否则 V 键 no-op）：XMP GPano 元数据 `UsePanoramaViewer=True`；或源尺寸宽高比 1.95–2.05（≈2:1）。
- 开启（手动，非自动）：全屏按 **V 键**（`ui_fullscreen.rs:28224` → `toggle_panorama_mode`）或点顶栏「投影」按钮（`ui_fullscreen.rs:22991`）；
  **Shift+V** 循环投影方式（`ui_fullscreen.rs:28220`）；检测候选且未开时弹「V キーで 360°ビューワー」toast（`app.rs:67369`）。
- 超大全景先弹「高品質で表示」横幅（`NeedsUserConfirmation`，`app.rs:15375`），点它才加载 8K base；可勾「今後も高画質モードで開く」。
- `is_panorama_mode_active` = `panorama_state.is_some()`（用户已 ON）**且** `detect_panorama` 命中（`app.rs:66534`）。

## 去 vendor 化路径（de-vendor egui 三件套）

目标：删 `vendor/egui`/`vendor/eframe`/`vendor/egui-wgpu` + `[patch.crates-io]`，回 crates.io。
- eframe：先升级 egui 栈 ≥0.34（PR#7905 已上游），再删；否则托盘 CPU 空转回归。
- egui-wgpu：mipmap 是硬阻塞，必须先把 mip 生成抽到应用侧或保留 fork，不可静默删（compare/panorama 画质退化）。
- egui：无补丁，自动跟着回。
- 二进制 vendor 勿动。
- 验收：托盘 CPU 不空转 + compare/panorama 无摩尔纹 + `cargo check -p mimageviewer` 过。

## mipmap 是什么（概念）

纹理的逐层减半预计算副本链（L0 原图→L1 ½→L2 ¼…），体积约 +33%。图被缩小/旋转时 GPU 自动选层+三线性过滤，
避免锯齿闪烁/摩尔纹。mImageViewer 仅 compare/panorama 用；普通看图 `ui_fullscreen.rs` 设 `mipmap_mode=None`，走 CPU Lanczos。
