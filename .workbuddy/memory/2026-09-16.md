# 2026-09-16

## NeoView vs QuiviT 阅读性能对比调研

- 产出：`docs/neoview-quivit-reading-performance-comparison.md`（含分段计时验证方案与优先级建议）。
- 结论：两边同为 WebView2，差距不在引擎，在三处——
  1. **预热窗口**（主因）：QuiviT `PRELOAD_HALF = 7`，目标页激活后 `100 + 45i` ms 错峰预取；
     NeoView 默认 `browser_predecode_pages = 1`、`MAX_CONCURRENT_PREDECODES = 1`、
     `PREDECODE_START_DELAY_MS = 350`，且 `useReaderSpeculativePreloadGate` 在每次
     keydown/wheel/pointerdown 后复位闸门（静默 280 ms + idle）→ 快速连翻时预取为零。
     `stableForMs < 120` 会让 `PreloadCoordinator` 直接返回 `admission: "paused"`。
  2. **归档字节路径**：QuiviT 走进程内 `quivit://` + 512 MB 内存字节缓存；
     NeoView 走回环 HTTP，且 `materialize-entry.ts` 把 CBZ 条目落 `mkdtemp(tmpdir())` 临时文件。
  3. **翻页主线程开销**：QuiviT 复用固定 2 个 `<img>`；NeoView 每页新建 `<img key={identity}>`
     + SVG filter 子树 + 6 个 effect，且缩放用布局尺寸（`natural × scale`）而非容器 transform。
- 根因背景：这是 `docs/neoview-reader-performance.md` 记录的 2026-07 无响应事故后的安全收缩，
  把投机工作压到了最小。可安全放宽的前提是保留现有 generation/identity 守卫与驱逐路径。
- 未实测，纯源码归因。

## 参考 QuiviT 的修复实施（同日）

实施时发现比「预取半径」更致命的一条：`useReaderAdjacentPagePreloader` 在
`plan.admission === "paused"` 时调 `cancel()`，而 `cancel()` = `releaseRetained(new Set())`
→ **每次翻页都先把上一轮预热出来的解码结果全部驱逐**，再等 350 ms 重新解码。
闸门与需求反相关只是表象，真正的浪费是「预热了又立刻扔掉」。

改动（均未增加 ReaderApp.tsx 行数，999 → 998）：

- `useReaderImagePreloader.ts`：`MAX_PREDECODED_PIXELS` → `MAX_PREDECODED_BYTES`
  （60M 像素 × RGBA 4 = 240 MB，预算不变只换单位，对齐事故文档预防规则 3）；
  `DEFAULT_PREDECODED_IMAGES` 1 → 3；`PREDECODE_START_DELAY_MS` 350 → 200；
  warm entry 重新归属当前 generation。
- 新增 `readerPreloadPolicy.ts`：`readerAdjacentPreloadEnabled`、`readerPreloadPlanRequiresRelease`
  （只有内存压力 / 失焦 / scrub 才释放，单纯「刚翻过页」只暂停不驱逐）。
- 新增 `useReaderFrameStability.ts`：如实上报导航静默时长（0 / 200 ms），
  替代 `stableForMs: speculativePreloadAllowed ? 1000 : 0` 这个布尔代理。
- `ReaderApp.tsx`：邻页预取 `enabled` 改用 `readerAdjacentPreloadEnabled`；
  `useReaderSpeculativePreloadGate` 仅保留给超分（`ReaderFrame.tsx:136`）。
- 默认值 1 → 3 同步三处：`DEFAULT_NEOVIEW_PRELOAD_CONFIG`、`INITIAL_PRELOAD_CONFIG`、
  `docs/neoview-migration.md` 的示例 TOML；`ReaderRuntimeConfig.test.ts` 的默认断言。
- `MAX_CONCURRENT_PREDECODES` 仍为 1（2026-07 事故守卫，未动）；
  因串行已天然错峰，**没有**照搬 QuiviT 的 `100 + 45i`。
- 明确不做：`materializeArchiveEntry` 内存化（要改 `MaterializedEntryLease { path }` port
  契约与全部消费者）、`PageImage` 节点复用 / 容器 transform 缩放、色彩滤镜 GPU 化。
