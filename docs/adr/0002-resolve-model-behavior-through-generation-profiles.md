# Resolve model behavior through generation profiles

Each supported model uses a versioned, data-defined Generation Profile to select fixed components and provide compatible defaults for sampler, scheduler, steps, guidance, and dimensions. Profiles are matched from model identity and metadata, may have local data overrides, and cannot embed compiler code. Effective profile data resolves through built-in profile, machine-local sparse override, then Project Document override. Objects merge recursively, arrays replace as whole values, and each sparse override records its base profile version. A built-in profile upgrade supplies new values only for fields that remain inherited; a removed, retyped, or newly invalid overridden field blocks compilation until confirmed instead of being guessed or discarded. The Fixed UI may expose advanced overrides, but the compiler validates them against the active profile before emitting a Prompt Graph instead of either locking every parameter or accepting incompatible combinations blindly. Last-used overrides are remembered per profile and never flow implicitly across model switches; copying settings to another profile is an explicit action.
