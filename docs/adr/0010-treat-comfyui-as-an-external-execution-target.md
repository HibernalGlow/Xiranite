# Treat ComfyUI as an external execution target

Comfygure uses the user's existing, manually started local ComfyUI installation through a configured ComfyUI Target instead of installing or managing another copy. A target records its loopback API endpoint and shared Library path; Comfygure only attaches to a running endpoint and never starts, stops, clones, upgrades, or modifies the ComfyUI process, core, Python environment, or custom-node directories. V1 compiles against node classes already reported by `/object_info`, disables unsupported capabilities with explicit diagnostics, and does not automatically install a `comfygure-nodes` companion package. Remote ComfyUI targets are unsupported and introduce no V1 configuration, transport, path-mapping, authentication, or compatibility commitments. This lets ComfyUI Desktop and Comfygure safely share the same Library without expanding the current product scope.
